# 首次使用与紧凑窗口修复

## 证据与根因

本轮对话未收到可查看的截图附件，因此不能对用户截图逐像素比对，也不能确认宿主 GPU、ClearType 或 Chromium 具体版本造成的文字重影原因。

通过浏览器回归测试实际复现：旧欢迎页在 800×544 已产生内部滚动，DPR 1、1.25、1.5 三项测试均失败。布局原因是宣传头图、大标题、多层说明和间距占用过多高度；欢迎区设置 overflow:auto，因此启用按钮落在滚动区域。app-shell 同时强制 min-height:400px，无法适应更矮宿主视口，外层 overflow:hidden 会造成裁切。

字体检查发现 Segoe UI Variable 优先、550/650 字重、8–10px 小字及负字距；这些不是已经证实的宿主重影根因，但会增加字体回退、合成字重和小字号栅格化风险。没有发现文字复制层、text-shadow 或 CSS zoom/transform 对标题缩放的实现，不采用关闭 GPU、改系统缩放等未经证实的绕过方案。

## 修复范围

- 首次使用保留三条必要说明：采集内容与本地保留、敏感标题和排除、运行范围与暂停删除；删除宣传图、口号、大标题及额外介绍。
- 自然内容高度的欢迎卡片，没有内部滚动容器；开始记录按钮明显且无需滚动。去除外壳最小高度，补全 html/body/app 高度和 flex 子区 min-height:0。
- 缩小侧栏、头部和筛选区空隙，标题使用常规系统字体、600 字重、正常字距和明确行高；小字最低 11px，移除 hover filter、背景 blur 及无效装饰。
- 只让历史长列表或长设置区域承担必要的纵向滚动；保留虚拟列表固定 82px 行高，避免破坏定位计算。
- 同意启用后明确回到 history，并在 DOM 更新后聚焦搜索；不修改采集器、持久化或桥接契约。

## 验证与限制

新增三项 Edge headless DPR 模拟，每项验证 800×544、600×400、480×360 CSS 视口：欢迎卡片不溢出、页面无横纵溢出、启用按钮完整在屏内；启用后时间线有可用高度、搜索聚焦且能返回匹配结果。测试截图在 screenshots/onboarding-compact-dpr-*-test.png，内容由测试桥接提供，绝非宿主真实采集截图。

同时执行既有浏览器流程、模块测试、类型检查、生产构建、产物检查和真实 Windows Win32→SQLite→暂停→重开测试，结果见 test-results.md。

**待人工验证**：实际 Windows 100%/125%/150% 缩放、uTools 内置 Chromium 字体栅格化与文字重影、跨显示器 DPI 切换、用户当前窗口尺寸，以及小于本轮覆盖范围的窗口。DPR 模拟不改变 Windows 系统缩放或 GPU 合成环境，不能将其标为实际 DPI 验收通过。请使用新包重载后，对相同问题位置进行截图对比。
