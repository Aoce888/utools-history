## 已定位并修复

原 preload 忽略 `onPluginOut` 的 isKill 参数，只停止 M1 实验采集器；生产服务仅依赖 beforeunload 清理。这会漏掉宿主发出终止通知时的主动清理机会，初始化未结束时也可能向已终止页面暴露服务。

修复为统一、幂等的 shutdown：`onPluginOut(true)` 和 beforeunload 都触发它；停止 helper、保存 repository、释放写者锁，重复通知不重复关闭。若 WASM 尚在异步初始化，初始化完成后关闭该实例，不提供桥接调用。`onPluginOut(false)` 保留生产服务，不改变用户暂停设置。

新增两个 preload 回归测试，在修复前均失败；修复后覆盖后台隐藏、终止、重复卸载、终止后的桥接拒绝，以及初始化中的终止竞态。这是模拟宿主回调的自动化验证，不是 uTools 实机证据。

## 行为与证据边界

| 情况 | 当前实现 | 验证范围 |
| --- | --- | --- |
| 首次加载、未同意 | 建库/读取设置，不启动 helper | 既有模块及打包 preload 集成测试；宿主待人工验证 |
| 开始/暂停/搜索 | 同意后启动；暂停停止并落盘；搜索本地库 | 自动化与真实 Windows 临时库集成；宿主待人工验证 |
| 插件隐藏到后台 | isKill=false，不停止生产采集 | 回调模拟通过；宿主是否保活待人工验证 |
| 结束插件/页面卸载 | shutdown，停止 helper、flush、释放锁 | 回调模拟通过；真实宿主触发顺序待人工验证 |
| uTools 正常退出 | 若收到结束/卸载通知，执行上述清理 | 待人工验证 |
| 强制结束宿主进程 | 无法保证回调；helper 每轮检查父 PID，数据库保留最近成功快照 | 代码审查；强杀时序、后台定时器及 PID 复用影响待人工验证 |

关闭面板可能对应隐藏，也可能结束插件，取决于宿主设置，不以“关面板”笼统推断。父进程消失的轮询退出并非操作系统强制绑定，不能宣称在所有异常条件下无孤儿进程。强杀仍可能损失最近约 5 秒数据；正常清理中的落盘失败仍需排查磁盘/权限。

## 包与宿主

生产包包含相对路径的 HTML、资源、preload、service、collector、SQLite WASM 与许可，manifest 移除 development 地址，解压后导入根目录 plugin.json。产物检查及打包 preload 测试不代替真实 uTools 加载。当前 Computer Use native pipe 与 browser host 均不可用，未修改任何宿主设置，也未将人工项标为通过。

依据：[uTools 事件文档](https://www.u-tools.cn/docs/api-reference/events.html) 将 isKill=false 定义为隐藏到后台，true 为结束运行；上表中关于实际触发与保活的判断仍需 [人工清单](manual-verification.md) 证据。
